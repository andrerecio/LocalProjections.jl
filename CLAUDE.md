# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A fork of [gragusa/LocalProjections.jl](https://github.com/gragusa/LocalProjections.jl) (remote `origin` is `andrerecio/LocalProjections.jl`, `upstream` is gragusa). The package estimates local projection impulse response functions via horizon-specific linear regressions with a formula DSL.

**Purpose of the fork:** extend the inference procedures beyond the current HAC/HC options, following `docs/src/inference_procedures_guide.md` — a mathematical guide covering (1) equal-weighted-cosine (EWC) HAR inference with fixed-smoothing Student-t_B critical values, (2) the Herbst–Johannsen local projection bias correction, and (3) the VAR residual moving-block bootstrap with Hall percentile-t bands. Read that guide before touching inference code; its §5 "safe adaptation checklist" and §6 audit are authoritative.

`docs/src/code/lp_var_nberma-main/` is the untracked third-party MATLAB replication suite for Montiel Olea, Plagborg-Møller, Qian & Wolf (2025) — the reference implementation the guide maps to. Treat it as read-only reference material: never format, refactor, or commit it.

## Architecture

`src/LocalProjections.jl` holds only the module header, exports, imports and the `include` list; the code is split by topic into plain `include`d files of **one module** (no submodules — tests reach ~25 private names (`LocalProjections._x`, or via aliases such as `LPj._x`) and the Makie extension imports `_critical_value`, `LPEstimate`, `LocalProjectionCovariance`). Include order, which matters only for types used in signatures/fields (keep every struct and `Union` alias in `types.jl` or in a file before its first use):

`utils.jl` (`_run_draws!`, `_check_level`) → `terms.jl` (formula DSL: `cumul`/`leads`/`anchor`/`|`/`ldiff`/`hbr`/`firstdiff` term types and StatsModels methods, `_lhs_at`/`_lhs_response`/`_lhs_tautological`/`_lhs_kind`, horizon tracking, `_create_cumulative`/`_create_anchored`, `_extract_base_variables`, `_float_column`/`_as_float_matrix`) → `types.jl` (`LPState`, `LocalProjection`, `LocalProjectionCovariance`, `LocalProjectionIV`, `LPResult`, `BiasCorrectedLP`, `LPEstimate`, their `show`/`+ vcov`) → `state.jl` (Ramey–Zubairy helpers, `statetest`) → `lp.jl` → `lpiv.jl` (`lpiv`, `first_stage`, `weakivtest`) → `inference.jl` (`stderror`, `IRFSummary`, `coefpath`, `vcov(::LPResult)`, critical values, `ewc_bandwidth`, `summarize(::LPEstimate)`) → `biascorrect.jl` (Herbst–Johannsen) → `var.jl` (`_var_data`/`_var_ols`, `lagselect`, Pope, `_var_irf`/`_var_ma`/`_var_simulate`/`_var_fevd`, `_check_var_rank`) → `varbootstrap.jl` → `fevd_core.jl` (`_gl_*` QR matrix core) → `fevd.jl` (`_GLSpec`/`_GLDesign`, `LPFEVD`, `fevd`) → `fevd_bootstrap.jl` → `fevd_summary.jl` (`FEVDSummary`) → `plotting.jl` (Makie stubs, RecipesBase) → `irfresult.jl` (`as_irf_result`). The split (commit `80c1314`) was a pure move; trace older history with `git blame -C -C` or `git log -S` (`--follow` does not cross it). Multi-method docstrings (`?summarize`) list methods in include order.

- **Formula DSL:** the LHS must be `leads(y)` (y_{t+h}), `cumul(y)` (cumulative), `anchor(y, z)` (y_{t+h} − z_t; `|` is pipe sugar, e.g. `leads(y)|z`), `ldiff(y)` (y_{t+h} − y_{t−1}, Piger–Stockwell), `hbr(x, y)` ((x_{t+h} − x_{t−1})/y_{t−1}, Hall–Barro–Redlick), or `cumul(ldiff/hbr)` (the changes summed over 0..h, baseline counted h+1 times — `CumulTerm{<:LongDiffTerm}` has its own `modelcols`); a plain LHS throws. `firstdiff(x)` gives Δx for `lags(firstdiff(x), p)`. RHS `lags(x, n)` and the OLS/IV engines come from Regress.jl. `lp`/`lpiv` build the RHS design matrix once, then loop `h = 0:horizon` rebuilding only the LHS through `_lhs_at(lhs_term, h)` (dispatch on the term type; `_lhs_response` and `_lhs_tautological` likewise) and calling `Regress.ols` (or IV) per horizon. A new response transform = a term type plus those three methods (and `_specialize_horizon`/`_has_dynamic_horizon`/`_tracks_horizon` if it may appear on the RHS). `missing` values are converted to `NaN` sentinels for type stability and rows are masked with `isnan` per horizon.
- **Estimation sample:** `lp`/`lpiv` take `sample = :horizon` (default, each horizon on its own complete-case rows) or `:common` (every horizon on `_common_rows`, the intersection of the per-horizon masks over `0:horizon`, computed in `_lp_estimate_horizons`/`_lpiv_estimate_horizons` before the loop). The choice is the last field (`sample`) of `LocalProjection`/`LocalProjectionIV`; `varbootstrap` passes it to every draw's `lp`, while `biascorrect` (nested `T₀ − h` samples), `varbootstrap(...; biascorrect = true)` and `fevd(::LocalProjection, data)` throw on `:common`.
- **State dependence:** `lp`/`lpiv` take `state`/`statelag`/`regimes`. The design is split as `[B .* (1 - I_{t-lag}), B .* I_{t-lag}]` block by block (exogenous incl. intercept, endogenous, instruments), names get a `_label` suffix, and the result carries an `LPState` in its `state` field (`nothing` when linear). `lp.shock` is then the *first-regime* name while `state.shock` is the unsplit one; tautological h=0 handling goes through `_shock_terms`. `statetest` needs the full per-horizon covariance (not the stored diagonals); `weakivtest(...; regime)` rebuilds RZ's one-regime regression from the stored `X`/`Z`. `biascorrect`/`varbootstrap` throw on state-dependent input. The state column's `missing`s are masked via `NaN` weights, not `dropmissing`.
- **Key types:** `LocalProjection` / `LocalProjectionIV` (holding a `Vector` of Regress models plus metadata; union alias `LPResult` for shared dispatch), `LocalProjectionCovariance` (stores only the per-term variance **diagonals** per horizon, not full matrices), `IRFSummary`. When `response === shock`, `tautological_h0` forces the h=0 coefficient to 1 and its variance to 0.
- **Inference** is delegated to **CovarianceMatrices.jl** through Regress.jl, with two equivalent idioms: `vcov(estimator, lp_result)` or `lp_result + vcov(Bartlett{NeweyWest}())`. `summarize(lp, cov; term, level)` builds confidence bands (currently always normal critical values — see EWC-1 below).
- **Lag selection & bootstrap:** `lagselect` ports `ic_var.m` (AIC/BIC on the VAR system, penalty denominator fixed at `T - p_max` but `Σ̂ₚ` from the full sample); `varbootstrap` ports the §4 procedure — `_var_ols` (`var_estim.m`), `_pope_biascorrect` (`var_biascorr.m`, validated against Pope's AR(1) closed form `b = 1 + 3ρ`), `_var_impact`/`_var_irf` (`var_ir_estim.m`/`var_ir.m`), `_position_means`/`_mbb_residuals!` (`var_boot.m`), `_var_simulate` (`var_sim.m`), and `_boot_interval` (`boot_ci.m`). Note `MacroEconometricTools` has **no** Pope correction, no Lyapunov solver and no lag-selection driver, and its `bootstrap_irf_block` recenters with a *stride-ℓ* mean rather than the sliding-window (Brüggemann–Jentsch–Trenkler) mean the reference requires — do not substitute it.
- **FEVD (Gorodnichenko & Lee 2020):** `fevd` ports `SubR2.m`/`SubLPA.m`/`SubLPB.m` and the per-horizon asymptotic variances of `SimulationAVar*.m` (MATLAB tree `docs/src/code/goro_lee_r2/`, gitignored, read-only). It reuses the `lp` formula front end (`apply_schema`, `modelcols`, `_lhs_at`) on a gap-free column table but **not** `lp`/Regress for estimation: a private QR matrix core (`_gl_r2`, `_gl_lp`, `_gl_lp_avar`, `_gl_lrv_nw`/`_gl_prewhitened_lrv`, `_gl_bandwidth`) keeps the reference conventions (own window `t0..T−h` per horizon, no dof factor in the Newey–West, full-sample shock moments). `LPFEVD` stores the compiled `_GLSpec`/`_GLDesign` so `fevdbootstrap` can re-run the estimator: `:var` reuses `_var_data`/`_var_ols`/`_var_simulate` plus `_var_ma`/`_var_fevd`/`_gl_lagselect` (HQIC on a common sample, MLE Ω — not `lagselect`), `:block` (R² only) and `:simulation` work from the stored design/moments. In `:var`, a level used only via `lags(firstdiff(y), p)` whose difference is a VAR variable is left out of the VAR and rebuilt per draw by cumulation (`_fevd_level_pairs`); `_check_var_rank` rejects singular VAR covariances. All bootstrap loops (incl. `varbootstrap`) run through `_run_draws!`. QR vs the reference's normal equations is rounding-level **except** after an exact-fit horizon (MP case, h = 0): the reference's prewhitened `se_pw` is then rounding-dominated at every later h and the package's differs materially (by design; tested in `testitems_fevd_octave.jl` when the local fixtures are present). Bands use MATLAB type-5 quantiles (`_gl_quantile5`), never clamped. Deviations from the MATLAB code are tabulated in `docs/src/tutorials/fevd.md`. The application data are `docs/src/data/gorodnichenko_lee.csv` (160×, Sec. 5) and `gorodnichenko_lee_rz.csv` (384×, App. H2), provenance in `gorodnichenko_lee_README.md`.
- **Re-exports:** several exported names are not defined here — `lags`, `first_stage`, `weakivtest`, `WeakIVTestResult`, `FirstStageIV` come from Regress.jl; `irfplot`, `irfplot!`, `LocalProjectionIRFResult` from MacroEconometricTools.jl; `lag`/`lead` from ShiftedArrays. Since Regress 0.2, `ols`/`iv`/`LagTerm` are `public` but **not exported** from Regress — qualify them (`Regress.iv`) or import explicitly.
- **CovarianceMatrices 0.32 API:** estimators are immutable (no `bw`/`kw`/`wlock`, no `setkernelweights!`); `vcov`/`aVar` return a `CovarianceMatrix` (an `AbstractMatrix`) carrying the fit metadata — read the selected bandwidth with `bandwidth(V)`, weights with `kernelweights(V)`, the bare matrix with `parent(V)`.
- **Plotting:** Plots.jl via `@recipe` (`plot(lp, cov; term, levels)`, `plot(b::LPBootstrap)`, `plot(f::LPFEVD)`, `plot(b::FEVDBootstrap)`), and Makie via the weakdep extension `ext/LocalProjectionsMakieExt.jl` (`irfplot`, `irfplot_axis`; `LPEstimate` with a covariance only — no bootstrap or FEVD methods). `as_irf_result` converts to MacroEconometricTools' `LocalProjectionIRFResult` (AxisArrays-based).

## Known issues (audited 2026-08-27, guide §6)

These are confirmed against the pinned trees and must be kept in mind when extending inference:

- **LP-1 (bug):** `lp`/`lpiv` call `dropmissing` on the base variables **before** constructing lags/leads, so internal `missing` values collapse the time axis and produce time-incorrect lags. Workaround: encode internal gaps as `NaN`, not `missing`. A proper fix must build lags/leads on the original time axis and mask incomplete rows afterward.
- **REG-1 (upstream bug in Regress.jl, still open in 0.2.0):** on OLS models `vcov(est, model; dofadjust=false)` is accepted but ignored for HAC/EWC. `LocalProjections.vcov` now forwards keyword arguments per horizon (2026-09-22). On IV models any keyword routes to CovarianceMatrices' generic sandwich: `dofadjust=false` equals the IV default for HR/HAC/EWC, `dofadjust=true` multiplies **only kernel HAC** by `n/(n−k)`.
- **REG-2 (upstream inconsistency in Regress.jl, verified 2026-09-20 to ~15 digits against Stata 17):** `lp` and `lpiv` covariances follow different conventions for the same estimator. (a) *d.o.f. factor:* on OLS models `n/(n−k)` is applied to `HR1`, kernel HAC and EWC (OLS kernel HAC ≡ Stata `newey`); on IV models it is applied to `HR1` but **not** to kernel HAC or EWC (IV kernel HAC ≡ unadjusted `ivregress`/`ivreg2` default). So `lpiv` kernel-HAC standard errors are smaller than `lp` ones by `√(n/(n−k))` per horizon (~5% with `k ≈ 20`, `n ≈ 200`), harmonize with `vcov(Bartlett(6), lpiv_result; dofadjust=true)` (kernel HAC only; EWC deliberately stays unscaled, the LLSW/`harreg` convention). (b) *automatic bandwidth:* **fixed upstream in Regress 0.2.0** (the IV path now gives the intercept kernel weight 0 too; `lp`/`lpiv` select identical bandwidths, tested in `test/testitems.jl`). **Deliberately not patched downstream** — a rescale in `LocalProjections.vcov` would double-count once upstream is fixed, and the upstream direction is undecided; drafts are in `upstream_issue_drafts.md` (Issue 3 open; Issues 2 and 4 fixed in Regress 0.2.0 / CovarianceMatrices 0.32; the former Issue 1 — EWC in `weakivtest` — was withdrawn, since `weakivtest` is not used with EWC; LocalProjections keeps its own warning). Do not "fix" either convention silently. Conventions for cross-checks: `Bartlett(bw)` ≡ `ivreg2 bw(bw)` ≡ `newey lag(bw−1)`; automatic bandwidths cannot match Stata (pilot length `20·(T/100)^{2/9}` with a cap there vs `4·(T/100)^{2/9}` in CovarianceMatrices), so only fixed-bandwidth Stata numbers are reference values.
- **Bootstrap scope:** `varbootstrap` supports OLS local projections with `leads` or `cumul` responses only; anchored responses and `lpiv` throw. `missing`/`NaN` in the VAR columns are rejected (the safe side of LP-1).
- **EWC-1 (methodological):** `summarize`, the plot recipes, and `as_irf_result` hard-code normal critical values; canonical EWC inference (Lazarus et al. 2018) pairs the EWC variance with Student-t_B critical values. Switching changes results — treat it as an explicit methodological change, never a silent refactor.
